## Problem

Most monitoring examples shell out to commands and parse their text. This project asks what it takes to expose real kernel statistics through a web API without that layer.

## Design

The metrics engine is a small C library built as a shared object. It reads `/proc/stat`, `/proc/meminfo` and `statvfs` directly. Flask loads it with `ctypes`, so a request calls straight into C with no subprocess and no output parsing. The API sits behind JWT authentication, stores metric snapshots in SQLite through SQLAlchemy so history can be queried by time, and accepts uploaded configuration files in a few formats, scoped to the user who uploaded them.

## Evidence

The README documents the full API surface: register, login, logout and profile; live CPU, memory, disk, process-count and uptime endpoints; a snapshot endpoint that also saves to the database; and history queries with a limit and a start time. A 100 ms sample in C is used for the CPU reading.

## Limits and next steps

There are no automated tests in the repository yet, and the library covers Linux on a single host only. The built shared object is committed to the repository and should be generated by the build instead. The API was also designed to be the host-telemetry component of a larger network monitoring idea.
